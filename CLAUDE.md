# Plateworks Desqueeze

A Mac tool for stills shot through an anamorphic lens. It sets the DNG `DefaultScale` tag, so Lightroom and Camera Raw show each photo at its correct shape. It converts Sony ARW files to DNG first. One Swift package, `DesqueezeCore` (`Sources/DesqueezeCore/`), holds every rule. Three front ends call it: a SwiftUI window (`App/PlateworksDesqueeze/`, generated by XcodeGen from `project.yml`), the command line tool `desqueeze` (`Sources/DesqueezeCLI/`, `Sources/desqueeze/`), and the MCP server `desqueeze-mcp`, a package of its own in `MCPServer/`. Three external programs do the file work: exiftool, dnglab, and Adobe DNG Converter, which is an optional backup. The human entry point is `README.md`.

This file is a router: the rules that must not break, and the one document to read for each change. It does not restate the documents. Everything else is in `docs/`, indexed at `docs/README.md`.

## Invariants

1. **The original is never at risk.** The app never changes or deletes an ARW. It moves one to the Trash only on the user's request for that run, and only an ARW that the run converted, after every check of design 14.2. The option is off by default and is never saved. It has no default value in the core, and the MCP server always gives `false`. A DNG keeps its `_original` backup until the tag reads back correctly. Then the backup goes to the Trash. Nothing is deleted.
2. **No pixels change.** The app sets tags. It never resamples or exports an image.
3. **The app does not touch a backup it did not make.** A DNG with an existing `_original` is blocked, not skipped: exiftool never replaces one. An orphan backup is reported and left.
4. **Only a pending ARW goes to a converter, and no converter writes over a file.** No converter starts when anything has the name `<base>.dng`. For a taken output name, dnglab refuses with exit code 6 and Adobe DNG Converter writes a second file, `_1.dng`. Never pass `-f` to dnglab. Never pass `-h` to Adobe DNG Converter: it opens a window and never returns.
5. **Each converter writes a hidden work file, and an exclusive rename gives the DNG its name.** Adobe DNG Converter gets the name with `-o`. A conversion passes only when the exit code is 0, the work file has bytes, and the rename passed. For dnglab, the match must also read back. Adobe returns 0 for a file it cannot read.
6. **Only the app's own files, checked backups, and originals on request go to the Trash.** A failed conversion sends only the exact work file of its ARW. Before a conversion, a leftover work file and exiftool's `_exiftool_tmp` beside it go there, and only when each is a regular file. A backup goes there after a good read-back. An original goes there only under invariant 1, through `BackupHandling.trashFile`, with one try: a refusal keeps it. Nothing else does.
7. **Top level only.** The scan does not enter subfolders and ignores hidden files.
8. **Every read and write of `DefaultScale` names `SubIFD`.** That is the directory Camera Raw reads. A DNG with an unknown scale is never skipped.
9. **The match table's numbers come from measurement.** Never estimate one. The table is a copy of the data file, and the drift check guards both against a new converter version or new firmware.
10. **`DesqueezeCore` and `DesqueezeCLI` import Foundation only.** AppKit and SwiftUI stay in `App/`. Only `MCPServer/` has third-party code. File work stays in the core, behind protocols, so tests use fakes.
11. **Every sentence that two front ends say is made once, in the core.** A front end reads a note's `kind`, never the English sentence. UI copy is sentence case, with no exclamation marks and no emoji. An error is one plain sentence, with the tool's own words on a detail line.
12. **Not sandboxed, offline, private.** No entitlements file exists, on purpose: a sandboxed app cannot start the programs. No network requests, no analytics.
13. **One run in a folder at a time.** A run holds an advisory lock on the folder itself (`Sources/DesqueezeCore/FolderLock.swift`). No lock file is made. A second run does not start, in any front end, and says the core's sentence. A scan and a dry run take no lock. On a volume that gives no lock, the run goes on without one, and a `noFolderLock` note says so. Any other error of the lock call stops the run.

## Working here

- Run the three suites before any claim of done: `swift test`, then `swift test --package-path MCPServer`, then `xcodegen generate` and `xcodebuild -project PlateworksDesqueeze.xcodeproj -scheme PlateworksDesqueeze -derivedDataPath build test`. The docs check runs inside the first and holds this file under 2,000 tokens.
- The tests on the real programs skip until `fixtures/` exists. Make it with `scripts/make_fixtures.sh` and one ARW. `fixtures/` is gitignored, and so is every ARW and DNG in the tree: the photo is private. Any Sony ARW that both converters can read works. The tests of the dnglab match skip for a frame that the match table does not cover.
- The drift check, `AdobeDriftTests`, needs both converters and a fixture frame that the match table covers. Run it after a new version of a converter or new camera firmware.
- A behavioral test counts only after it fails against a break.
- Never test on a real shoot folder. Copy it first.
- No test reaches the real Trash or the saved settings. `FileBackups` takes the trash function as a parameter, and a built tool takes `DESQUEEZE_TEST_BACKUP_FOLDER`.
- The window's tests have no app host, so they start no app. For a check by hand, start the app with `-openFolder <path>`, `-simulateMissingTools YES`, `-simulateMissingDnglab YES`, or `-simulateMissingAdobe YES`. The last two together hide both converters.
- `scripts/docs_check.py` is a copy of the documentation standard's check. Its header comment differs, and it has no skip rule for paths outside the repo. Never edit its checks here.
- Commit messages: `area: what changed`, a lower-case start, no period.
